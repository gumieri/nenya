## [Unreleased]

### Fixed

- **The injection variant-taxonomy union actually unions (NENYA-256, AUD-37)**: the NENYA-147 variant pass is documented as *"run the pass over the normalized candidates as well and **union** the hits"*, but the loop carried a `break` — it stopped at the **first adopting candidate**. A second obfuscated phrase that only the *next* candidate repairs (e.g. a soft hyphen *between* words, which only the spaced normalization restores, while an earlier phrase needed the joined one) was never counted and could ride through behind the first hit. The loop now runs every candidate with accumulating seen-sets — a phrase two candidates reveal is counted once, the raw pass's hits are still never double-counted. Pinned by a two-phrase payload (joined-only + spaced-only soft-hyphen splits): pre-fix 1 hit, post-fix 2; single-phrase guard stays at exactly 1 (mutation-verified by restoring the `break`).

- **The `non_chat_models` empty-list opt-out is expressible through conf.d drop-ins (NENYA-255, AUD-46)**: `mergeValue` ignored empty slices, so a drop-in's `"non_chat_models": []` — the documented operator intent ("an explicit list, *including an empty one*, is the operator's intent", per `mergeProviderRouting`'s own comment) — could never clear a base list, and `ApplyNonChatDefaults` then re-filled the defaults: a drop-in-defined provider could not opt out of the decision-only classification at all. The merge now skips a slice only when it is **nil** (field absent); a non-nil slice, empty included, is explicit and lands. Absent fields still preserve base values — only what the file literally says wins. Pinned by four sub-cases (drop-in clear / absent preserves / opt-out survives `ApplyNonChatDefaults` / unset still receives defaults; mutation-verified by restoring the empty-slice skip).

- **One canary-trailer matcher for both surfaces (NENYA-254, AUD-47)**: the adapter's trailing-marker matcher required the canonical wire envelope (`"[internal-ref] " + marker`) while routing's stable-history census matched the **bare** `NENYA-CANARY-` prefix anywhere in message content — a conversation that merely quoted or echoed a canary token was excluded from the census (a multi-turn conversation censused as one-shot, anchoring silently skipped) while the adapter correctly treated the same message as real history. The matcher now lives once, in the canary's owning package (`pipeline.MatchesTrailingMarker`), and both surfaces call it: only the enveloped trailer is gateway-produced; a bare token is conversation content. Pinned by a 2-message scenario where a quoted token decides the census (mutation-verified: the loose matcher fails it).

- **The auto-cache stand-down deep scan fails closed on truncation, with a visible outcome (NENYA-253, AUD-34)**: `hasClientCacheControl`'s budget-bounded walk returned a bare bool — on exhaustion (a 20k+-node request) it reported "no client marks", and `applyAutoCacheBreakpoints` **injected the gateway's anchors over a request whose marks it had never scanned**, violating the never-rewrite-a-client-mark invariant (NENYA-185) with nothing but a Debug line for the operator. The scan now reports `(found, truncated)`; a truncated result is **inconclusive**, the stand-down records `skipped_scan_truncated` (registered in the closed outcome set — an unregistered string collapses to `other`), and injection is skipped. Pinned by a 22k-node payload with a `cache_control` buried past the budget: pre-fix it anchored (`System:true Messages:true`), post-fix it stands down with the outcome counter at 1 (mutation-verified by restoring the fail-open call).

- **Buffered OpenAI→Anthropic conversion reports its unsendable markers (NENYA-252, AUD-33)**: `appendOpenAIContentArray` substitutes visible `[unsendable content: <type>]` markers for parts the Anthropic shape cannot carry (NENYA-176), but the conversion had **no `DropReport` parameter** — the fidelity loss never reached the reporting surfaces, so the client saw no `X-Nenya-Dropped-Content` header and `nenya_unsendable_content_total` never fired for this direction (the A→O branch of the same call site reported; the O→A branch was silent). Added `ConvertOpenAIResponseToAnthropicBodyReported`, threaded the report through `convertOpenAIToAnthropicResponse` → `extractOpenAIChoiceContent` → `appendOpenAIContentArray` with `Add` at both marker sites, and wired the buffered proxy call site symmetrically. The unreported entry point stays nil-safe. Pinned by marker + `Kinds()` assertions (mutation-verified: dropping the `Add` call fails with "marker without a report is a silent loss").

- **Unknown finish reasons no longer forwarded onto the Anthropic `stop_reason` enum (NENYA-251, AUD-32)**: both reverse mappings (`OpenAIToAnthropicTransformer.mapFinishReasonReverse` streaming, `AnthropicAdapter.mapFinishReason` buffered) fell through `default: return reason` — a provider's custom or case-drifted finish reason (`eos`, `STOP`, aggregator inventions) rode **verbatim** onto Anthropic's **closed** `stop_reason` enum, which strict clients reject. Known semantics are now mapped explicitly (`content_filter` → `refusal`, legacy `function_call` → `tool_use`) and anything unknown lands on `end_turn`, the neutral natural-stop. Symmetric with the forward transformer's existing `refusal` → `content_filter`. Pinned at both collection points — the held `message_delta` tail and `ConvertOpenAIResponseToAnthropicBody` (mutation-verified: the verbatim default fails 3 table cases).

- **Index-less tool-call deltas no longer dropped by the OpenAI→Anthropic reverse transformer (NENYA-250, AUD-31)**: `processToolCall` returned nil when a tool-call delta's `index` wasn't numeric — some providers omit `index` when the stream carries a single tool call, and the entire call vanished (no `content_block_start`, no arguments, a `tool_use` stop for a block that never opened). An absent/non-numeric index now defaults to 0, the conventional interpretation; explicit indices are unchanged. Pinned by a full three-chunk scenario (start → two argument deltas → `tool_calls` finish → held tail) asserting the accumulated `partial_json` and the stop events (mutation-verified: the pre-fix drop fails with "the index-less tool call was dropped").

- **`finishOnContextDone` no longer drops the event terminator nor skips `OnStreamClose` (NENYA-249, AUD-30)**: when the request context is done mid-stream, a **zero-length read** hit the `len(p) > 0` guard and fell straight to termination — discarding the pending event separator (the client's last event stayed undeliverable per SSE framing, NENYA-169's concern exactly) — and the terminal branch bypassed the observer notification every other stream end funnels through, so egress watchers and held-tail drains (`TailFinisher`, AUD-29) never saw the close. The zero-length read now defers via `(0, nil)` (legal per the `io.Reader` contract) and the terminal branch notifies `OnStreamClose` once under the same `closed` guard as the drain path. Pinned by a pipe-driven pending-separator scenario (event delivered → cancel → `(0, nil)` → terminator → `context.Canceled` with exactly one close; mutation-verified: the pre-fix form fails with "zero-length read = (0, context canceled)").

- **Cap-normalization telemetry fires once per logical request (NENYA-248, AUD-35)**: the payload is **restored to the client's original shape** between failover attempts (NENYA-179), so every attempt re-detected and re-recorded the same client-shape findings — `nenya_duplicate_params_total` and `nenya_param_coercions_total` inflated by the attempt count. Both recordings now gate on a per-request telemetry flag carried in `TransformDeps` (the AUD-39 mechanism, consolidated into a `RequestTelemetry` struct with the unknown-fields flag); the **mutation stays unconditional** — only the recording is gated, since the restore exists precisely so the next target sees the client's shape. Callers without request scope (MCP buffered loop, stream continuation) pass nil and keep per-attempt semantics. Pinned by counter deltas: 3 attempts sharing one request record once; nil records 3 (mutation-verified: ungating fails with "counter = 3, want 1").

- **`applyMaxTokens`'s clamp branch honors the NENYA-186 type contract (NENYA-247, AUD-36)**: the set branch stored the canonical JSON numeric type (`float64`) — its comment says so explicitly, "so later comparisons never no-op on a type mismatch" — but the **clamp branch stored a Go `int`**. A later clamp (a smaller-cap failover target) then hit the `float64` type assertion with `!ok` and **silently kept the larger cap**: the exact no-op the contract exists to prevent, introduced by the clamp's own store. Pinned by a two-step clamp test (5000 → 1000 → 500 must land on 500 as `float64`) plus the set branch (mutation-verified: the int store fails with "want float64 500").

- **A nil `TransformDeps.Logger` degrades to silence, not a panic (NENYA-246, AUD-38)**: twelve transform/sanitize sites dereferenced `deps.Logger` directly — `TransformDeps` is exported, and a caller (or test harness) that omits the logger turned every best-effort `Debug`/`Info` into a mid-request nil-pointer panic. All sites now go through a nil-safe `log()` accessor backed by a package-level discard logger (no hot-path allocation). Pinned by driving two deliberate sites — `stripStreamOptions` (asserts the strip still happened) and the DeepSeek reasoning-injection path — with a nil logger (mutation-verified: a direct deref panics with a nil pointer dereference).

- **The unknown-fields audit fires once per logical request (NENYA-245, AUD-39)**: `auditRequestFields` ran inside the per-attempt transform, so a request that failed over N times incremented `nenya_unknown_request_fields_total` N times and duplicated the Warn N times — the counter counted dispatches-with-unknown-fields while its documented semantics were requests-with-unknown-fields. The retry loop now owns a shared flag threaded through `TransformDeps.UnknownFieldsAudited`, gating the audit to the request's first transform; callers without request scope (MCP buffered loop, stream continuation) pass nil and keep per-attempt semantics deliberately. Pinned by counter deltas: 3 attempts sharing one flag count once; a nil flag counts 3 (mutation-verified: unwiring the gate fails with "counter = 3, want 1").

- **Malformed image parts report `malformed_image`, not `format_media` (NENYA-244, AUD-41)**: an `input_image` with **neither a URL nor a media type** produced `imageRef{mime: ""}`, and the empty mime missed every format's media table — so the drop counter blamed **`format_media`**, pointing operators at a format-capability problem that did not exist. The documented `malformed_image` reason existed but was never produced. The drop reason now names the real cause when an image part has no URL and no mime; genuine media mismatches (a mime the target's table rejects) still report `format_media`. Pinned by a reason table: malformed on both sites, valid data-URL kept, remote-URL reason paths, and a true mismatch still `format_media` (mutation-verified: the fall-through fails the malformed cases).

- **Passthrough retries rebuild the upstream request per attempt (NENYA-243, AUD-21 hardened)**: the System One and embeddings retry closures re-`Do`ed a request built **once outside** the closure. Verified against Go 1.26: the symptom does **not** reproduce for bytes-backed bodies (`NewRequestWithContext` snapshots `GetBody`, and the client re-sends the full body on a second `Do` — probed directly), but the shape is fragile (any future body type without `GetBody` would send an empty retry) and inconsistent with `doUpstreamRoundTrip`, which has always rebuilt inside the closure. Both routes now rebuild per attempt like their sibling. Pinned by an end-to-end retry test: a 5xx-then-200 upstream must receive the full request body on **every** attempt and answer 200 (the test is mechanism-independent — it fails on empty/truncated retries whichever way the runtime evolves).

- **Streaming usage callbacks surface `AmbiguousCacheSemantics` (NENYA-242, AUD-27)**: the normalizer computes the flag (OpenAI-style input total + Anthropic-native cache field names + no decomposition) and the streaming consumer has an entire fold-note handler for it — but the reader **never copied the flag into `UsageData`**, so the streaming handler was dead code and only the buffered path surfaced the ambiguity. One-line population in the callback construction. Pinned by an ambiguous-shape SSE stream asserting the flag arrives on the callback, plus a control (decomposed OpenAI usage stays unflagged) (mutation-verified: dropping the field fails with "must surface AmbiguousCacheSemantics").

- **Reverse transformer publishes real usage under the standard `include_usage` ordering (NENYA-241, AUD-29)**: OpenAI streams end `…finish_reason chunk → usage-only chunk → [DONE]`. The OpenAI→Anthropic converter emitted its closing `message_delta` **at the finish chunk** — before the usage arrived — so Anthropic-native clients saw `input_tokens: 0, output_tokens: 0` (or a char estimate), while the late-captured real usage was swallowed. The tail (`message_delta` + `message_stop`) is now **held** at finish and flushed by the trailing usage chunk, or by the stream terminal when no usage chunk follows. The reader gained a `TailFinisher` extension that composes the held tail into its end-of-stream sequence (`finishStreamFrames` / `injectDoneOnly`), since `[DONE]` is intercepted before transformers see it; the `[DONE]` sentinel is consumed only when a tail was actually flushed there. Pinned by `UsageAfterFinish` asserting the finish chunk holds the delta and the usage chunk flushes it with the real counts (mutation-verified: publishing at finish fails with "got usage map[input_tokens:0 output_tokens:2]").

- **OpenAI-shape cache decompositions derive the cache-miss remainder (NENYA-240, AUD-28)**: the usage normalizer's own invariant is *hit + miss + creation == prompt* — the Anthropic and Gemini branches derive the miss as the remainder, but the **OpenAI branch left it 0** whenever the upstream decomposed via `prompt_tokens_details.cached_tokens` without an explicit miss field. Partially-cached OpenAI-shape traffic therefore reported **100% hit rate**: miss counters (`Stats.RecordCacheMiss`, `nenya_cache_miss_tokens_total`) and the trace's cache attributes never saw the uncached tokens. `openAITotals` now derives the remainder when a decomposition exists and no explicit miss was reported; an explicitly reported miss always wins. Two table cases that codified the old zero were updated to the invariant. (Mutation-verified: reverting fails with `CacheMiss:0, want CacheMiss:20`.)

- **`/v1/models` listings are deterministic (NENYA-239, AUD-18)**: agents are a Go map and the discovery catalog iterates its own map, so the assembled listing order **varied per request** — the Anthropic dialect's `first_id`/`last_id` flapped between calls and clients diffing the listing saw phantom churn. The listing is now sorted by model ID (unique — the seen-set dedupes), making every call byte-stable. Pinned by 25 repeated listings asserting identical order plus sorted IDs, and the dialect extremes (`first_id=alpha`, `last_id=echo`) across all 25 (mutation-verified: the unsorted order fails with "listing order varies between calls").

- **Agent names containing colons are rejected at load (NENYA-238, AUD-40)**: the circuit key is `agent:provider:model`, and both positional parsers — the **per-agent breaker threshold lookup** (first colon-delimited field) and the **backoff metric labels** (`SplitN(key, ":", 3)`) — silently misread an agent whose name contains a colon: `my:agent`'s custom thresholds fell back to the defaults while its metric labels were scrambled (`agent=my`, `provider=agent`, `model=provider:model`). The key format cannot represent such names, so load-time validation now rejects them (and empty names) with a clear rename hint instead of the silent corruption; ordinary names and colons elsewhere (e.g. a `gpt-4o:latest` model) are unaffected. Pinned through the validation collection point — the test drives `ValidateConfigReferences`, so an unwired validator fails it (mutation-verified: unwiring produces "expected an error, got none" on both cases).

- **Exact-limit bodies are accepted (NENYA-237, AUD-23 verified)**: a non-streaming request body of **exactly** `max_body_bytes` (default 10 MiB) is accepted — the limit is inclusive end to end. AUD-23 reported an exact-10-MiB body being rejected as over-limit; verified **not reproducible** on Go 1.26 (`http.MaxBytesReader` passes an exact-n body — verified against the runtime directly — and every body-reading route defers to it). Pinned anyway: an e2e test posts a body of exactly 10 MiB through admission, auth, agent scoping and validation and fails if any stage ever answers 413, so a future off-by-one (or a Go behavior change) cannot land silently.

- **Model-limit registry fallbacks match plain IDs case-insensitively (NENYA-236, AUD-42)**: `ResolveModelLimits` and the transform-side max-output/context fallbacks looked `config.ModelRegistry` up with the **client's exact spelling** — a request for `GPT-4o` while the registry keys `gpt-4o` missed, so the model silently lost its context window and output cap (wrong truncation budgets, wrong output reservation). The fallbacks now fold plain-ID spellings, reusing the established NENYA-146 carve-out: **opaque IDs** (ARNs, slashed, dotted) stay exact, because the dispatch keeps the client's spelling verbatim and must not match a differently-cased variant. (The discovery-catalog lookup stays exact too — its keys mirror the upstream's own spellings.) Pinned by fold tests on all three sites plus the opaque exactness carve-out (mutation-verified: reverting to exact lookups fails with `(0, 0)` / `= 0, want …`).

- **Dead `defer action.cancel()` removed from `handleUpstreamError` (NENYA-235, AUD-49)**: both callers already own the cancel — the chat loop cancels **before entry** (`handleActionError`, right after consuming the error body; its own comment notes later cancels are harmless) and the MCP buffered loop **right after return** — so the defer was a redundant third cancel on every path. Worse, it was a **trap**: any terminal path invoked with a cancel-less action panicked at the deferred nil-func call. Removed; the cancellation contract is now documented on the function. Pinned by driving all three terminal paths (model-not-found failover, non-retryable failover, last-target done) with cancel-less actions — pre-fix this panics with a nil pointer dereference (mutation-verified by restoring the defer).

- **Request-trace summaries cover dispatch-bearing requests only (NENYA-234, AUD-26)**: the handler's comment claimed the summary defer was "registered after `validateChatRequest` so body-read failures and the cache-hit sentinel do not emit a misleading summary" — but the code registered it **before** validation, so every malformed body produced an Info `request trace` record with zero stages and zero tokens. The comment described the intent; the code now matches it: the defer gates on validation outcome (`req != nil && herr == nil`), so a request that never dispatched emits no summary while every dispatch-bearing exit path still does. Pinned end-to-end: a malformed body emits no summary, a validated request emits exactly one (mutation-verified: the unconditional defer fails with "a body-read failure must not emit a request-trace summary").

- **Mid-request level check threads the request context (NENYA-233, AUD-25)**: the synthesized-session-header debug gate called `Logger.Enabled(context.Background(), …)` mid-request. Standard handlers ignore the context, so behavior is unchanged with them — but a request-scoped or trace-aware handler can only make per-request decisions if handed the request's context, and the project's context standards forbid a detached `Background` on the request path. The check now probes `r.Context()`. (The response-cache and span-`End` sites are deliberate: those APIs carry no context, and `End` is terminal.) Pinned by a probe handler whose `Enabled` records whether it received a marker-carrying request context (mutation-verified: `context.Background()` fails with "did not receive the request context").

- **`ReportSuccess` persists a snapshot, not the live account pointer (NENYA-232, AUD-43)**: the success path handed `SaveAccount` the **live** `*ProviderAccount` (from `GetAccount`, whose pool lock is released on return), so persistence marshaled `ModelLocks`/`ModelBackoffLevels` while any concurrent `ApplyError`/`ReportSuccess` mutated them — a data race the `AccountSnapshot` helper exists to prevent, and which the `ApplyError` path has always avoided. The success path now uses the same snapshot. Pinned by a pointer-identity test (`SaveAccount` must not receive the pool's live pointer) plus a concurrent mutator/marshal hammer — the mutation check fires **twice** under `-race`: the identity assertion fails *and* the detector flags the unsynchronized map read.

- **Draining a stall reader no longer leaves its timer armed (NENYA-231, AUD-48)**: `DrainPending` closed the stall channel but never stopped the stall timer — and the stream-continuation path (`finishStreamAttempt`) calls `DrainPending` alone, without `Stop`. Every finished continuation left a timer armed for up to a **full stall timeout** after the response: the armed callback pinned the reader in memory, and a late read-loop delivery **re-armed** it (the reader was never marked stalled, so `serveResult` happily `Reset` the timer). `DrainPending` now delegates to `Stop` (idempotent — the passthrough site's Stop-then-drain is unchanged in behavior). Pinned by a test that drains, asserts the timer is no longer pending, and that a late delivery cannot re-arm it (mutation-verified: the close-only form fails with "the stall timer is still pending after DrainPending").

- **Expired model locks are swept (NENYA-230, AUD-44)**: the pool already had `ExpiredLocks`/`CleanupExpiredLocks`, but **no code path ever called them** — every `(account, model)` pair that ever received a model-scoped lock stayed in `Account.ModelLocks`/`ModelBackoffLevels` forever, an unbounded-growth leak on long-lived processes paid again on every account-state snapshot. The gateway now runs a `LockSweeper` (constructor-started, stopped in `Close`, one-minute default cadence; the reload drain stops the replaced gateway's sweeper with it). Pinned by a convergence test (expired lock + backoff level removed, live lock untouched), a lifecycle test (`Stop` joins, idempotent), and a gateway test that `New` starts and `Close` stops the sweeper (mutation-verified: unwiring fails with "New must start the model-lock sweeper").

- **Quota exhaustion no longer leaks across concurrent requests (NENYA-229, AUD-13)**: the retry loop signaled "this failure was quota exhaustion" through **one process-wide atomic** on the `Proxy`. Any concurrent request's loop could consume the leftover flag on its next unrelated error — telling that client `error_kind=quota_exhausted` for an upstream that never said quota — or clear it before the owning request read it, downgrading a real quota failure to a generic `provider_error`. The MCP buffered path made this worse in both directions: it never read the flag (its quota signals were silently lost) while its calls parked state that poisoned the next chat request. The signal is now returned per classification call and OR'd into the owning loop's flag only; the shared atomic is gone. Pinned by a four-step sequential test that drives the classify step directly (the operation that used to park the flag), then an unrelated loop's plain error (which used to inherit it) — mutation-verified by reintroducing the park-and-consume pair, which fails with "loop B must not inherit request A's parked quota signal".

- **CodeQL-flagged allocation sites hardened (NENYA-228)**: the five `make()` capacity computations CodeQL flagged for potential integer overflow now use the overflow-safe `util.AddCap` clamp — the `/statsz` line collector (`internal/proxy/handler.go`), the cache-breakpoint claim copy (`internal/adapter/anthropic.go`), the context-limit summary splice (`internal/proxy/context_limit.go`), and the two byte-splice allocations in `nenya config set`. Behavior is unchanged for every reachable input (the overflow case is unreachable at 64-bit scale); the guards exist to keep the static-analysis gate clean. The three `go/weak-sensitive-data-hashing` alerts were dismissed as false positives: SHA-256 there hashes request bodies, `agent:model` identity strings, and API tokens purely as idempotency/cache-namespace keys — never for secret verification, where a deliberately slow hash would be required.

## [v0.18.0] - 2026-10-23

A security and reliability release: all 12 P0 findings from the cross-wave audit, plus five adjacent P1 fixes.

### Security & reliability highlights

- **Reload is now safe under load** — a SIGHUP no longer closes the serving gateway under in-flight requests (SecureMem, MCP clients, cache and quota fetcher stay alive until the requests drain), the reloaded quota poller feeds the carried billing tracker, and the new response cache reports into the process-wide metrics.
- **Egress filtering covers every wire format** — ExfilGuard, the canary tripwire, the secret filter and the entropy filter now scan Gemini-native chunks and every text surface of a chunk, not just first-text OpenAI deltas; EOF-terminated URLs are evaluated on both surfaces; the held tail flushes at every terminal shape.
- **MCP tool loops work on non-OpenAI-format chains** — tool calls are extracted from Anthropic `tool_use` and Gemini `functionCall` shapes (previously invisible, so chains replayed tool calls unexecuted), the transport tolerates the no-space SSE field spelling, and the recovery transport swap is now synchronized (the long-standing `-race` flake in `TestClient_Recover_ConcurrentSingleFlight`).
- **Converted Anthropic streams are properly framed** — each synthesized event gets its own `event:`/`data:` frame instead of being glued onto one invalid JSON line.
- **Route and header matching tightened** — prefix routes require a path-segment boundary (`/v1/responsesXYZ` no longer reaches the responses handler), and `required_headers` matches case-insensitively.
- **A BYOK 429 no longer contaminates the shared account** — no pool eviction, cooldown or breaker charge for a caller-funded request.

### Upgrade notes

- **Metric renames**: `nenya_billing_spend_usd` → `nenya_billing_spend_cents_total`, and `BillingTracker.TotalSpendUSD` → `TotalSpendCents` (both always carried cents). Update dashboards and alerts.
- **Response-cache fingerprints now carry the content-policy identity**, so editing a guardrail knob (or giving an agent its own overrides) yields misses for entries stored under the previous policy. In-memory only.
- **Semantic cache partitions per bearer token**: multi-key deployments no longer share semantic entries across keys (single-key is unaffected).
- **`/statsz` usage reporting**: Anthropic- and Gemini-native usage now reports true `cache_hit_ratio` and `cache_miss_tokens`, and `total_requests` counts dispatches rather than usage chunks.
- **New knob**: `governance.reload_drain_timeout_seconds` (default 30s, max 600) bounds a reload's drain.
- **Weak credentials refuse boot** (NENYA-192): installs with placeholder tokens will not start — see "Upgrading from earlier versions" in `docs/SECRETS_FORMAT.md`.
- **`nenya config set` now preserves JSONC comments and key order** instead of rewriting the file.

### Fixed

- **A BYOK 429 no longer contaminates the shared provider account (NENYA-225, AUD-22)**: the 429 handler unconditionally evicted the provider's pooled connections and recorded a cooldown + breaker failure. For a caller-funded (BYOK) request the 429 is the **caller's** account hitting its limit, so the gateway was dropping warm connections every other tenant shares and benching a target whose shared credential was perfectly healthy — exactly the cross-tenant contamination BYOK exists to prevent. The handler now stands down on every shared-account write for a BYOK target (logged), while returning the retry delay so the caller's own retry still works; shared-account 429s are unchanged. Pinned by a paired test (BYOK: no circuit, no cooldown, stand-down logged; shared: cooldown still recorded — so the fix cannot be a blanket disable; mutation-verified).
- **`nenya config set` preserves JSONC comments and key order (NENYA-224, AUD-45)**: the command decoded the document into a map, mutated it, and re-marshaled — destroying every operator comment and reordering keys (Go maps have no order; `json.MarshalIndent` sorts). Config files are JSONC and operators annotate credentials and overrides, so a `config set` was silently erasing documentation. The edit is now a byte splice: the target's span is replaced (or a member inserted into its parent object) and every other byte — comments, order, formatting, escapes — is preserved. The scanner handles `//` and `/* */` comments, structural characters inside strings, and nested objects; the result is re-validated as JSONC before it is written, so a splice bug can never leave an unparseable config. Pinned by splice unit tests (comment/order preservation, in-place replacement, nested creation, empty document, strings containing braces/commas) and an end-to-end on-disk test through `setConfigKey` (mutation-verified: the map round-trip fails with "comment lost on disk").
- **`required_headers` matches header names case-insensitively (NENYA-223, AUD-19)**: the MCP server check looked a required header up with an exact map key, so a server declaring `required_headers: ["Authorization"]` while the operator configured `authorization` named the same header (RFC 9110 §5.1) but was judged missing — the server never connected and **every request selecting it failed closed with a permanent 503**. Lookup is now case-insensitive (an exact-spelling entry still wins), and load-time validation Warns when a declared required header is configured in no spelling, so the fail-closed shape is visible before it reaches traffic. Pinned by a case table (canonical/lower/UPPER/mixed, blank-value, second-header, none) plus a tie-break test (mutation-verified: the exact-match lookup fails all three case-mismatch cases).
- **Prefix routes no longer accept undeclared look-alike paths (NENYA-222, AUD-20)**: the router matched prefix routes with a bare `strings.HasPrefix`, so `/v1/responsesXYZ` resolved to the responses handler, `/v1/filesX` to files, and so on — an undeclared path was accepted, authorized against the wrong endpoint's shape, and forwarded upstream (the `/v1/responses` canonicalizer had the same over-broad check, so a look-alike could also skip the model-required guard as an "id-addressed operation"). Routing and the responses canonicalizer now share `hasPathPrefix`, which requires a segment boundary (`base` exactly, or `base + "/…"`; a base already ending in `/` stays a segment prefix). Genuine sub-paths (`/v1/responses/resp_1/cancel`, `/v1/files/file_1/content`, `/proxy/…`) are unaffected. Pinned by a matcher table, a router table, a canonicalizer check, and an end-to-end 404/no-dispatch test (mutation-verified: reverting to the bare prefix fails with "found handler = true").
- **A SIGHUP reload's response cache reports into the process-wide metrics (NENYA-221, AUD-17)**: `newGateway` built a fresh `infra.Metrics` instance and wired the `ResponseCache` (and discovery) to it, then `Reload` overwrote `newGW.Metrics` with the carried instance — the cache's hit/miss counters went to a discarded object, so the operator-visible series silently stopped moving after every reload. It also skips one-shot requests (a single turn has no stable boundary to anchor), skips requests whose history the content pipeline window-compacted (the compacted head is a gateway-produced region, and anchoring it would promise stability the gateway cannot keep), and requires `prefix_cache.enabled`. Every outcome is counted (`nenya_auto_cache_breakpoints_total{outcome}`: injected or the stand-down reason), so an operator can see why anchoring did not happen; an opted-out agent emits nothing. A byte-stability test pins that the anchored prefix is identical across turns (the new turn never leaks into it), which is what makes the provider cache actually hit.

- **Token estimation: images, framing, declarations, and a class-weighted fallback (NENYA-157)**: the request estimate fed every budget-critical decision (per-target input budgets, trimming, pipeline savings), yet it counted only message TEXT — an image block was the two tokens of the literal `"[image]"`, the per-message framing and the tool/structured-output declarations were invisible, and a failed BPE initialization returned zero, unbounded every budget. `CountRequestTokens` now composes: cl100k BPE of the message text (image placeholders excluded, so images are priced once) + 4 tokens of provider framing per message + the declarations (serialized tool/`response_format` text + 8 tokens of framing each) + each image by pixel area. Scalar, slice, and pointer-to-scalar element values remain last-file-wins; inside struct entries zero/empty mentions leave the base value, so a drop-in can override but never reset or clear a base setting (the same rules now also govern `governance.judgments` entries, where `"site": null` is a no-op).
- **Per-agent breaker thresholds wired (NENYA-204)**: `agents.<name>.failure_threshold` and `success_threshold` were documented but silently ignored — the shared circuit breaker always used the package defaults (5/1). The breaker now consults a per-key threshold resolver (agent = the first field of the `agent:provider:model` circuit key); `0`/omitted inherits the defaults, so existing configs are unchanged. Two agents with different thresholds demonstrably trip at different failure counts, and per-agent HalfOpen success thresholds govern recovery.
- **ExfilGuard cross-chunk head leak fixed (NENYA-205)**: the egress guard now withholds the whitespace-free tail of the stream — text that could still grow into a URL construct — instead of streaming it, and re-evaluates it prepended to the next delta, so a violating URL split across any chunking (at every offset, including inside multi-byte runes) is spliced whole rather than leaking its head and query payload (constructs within the 4096-rune detection window; a single delta larger than the window can still expose a construct's head). The hold is bounded by the detection window (force-emit keeps the window's visibility over everything withheld), `Flush` emits the tail at stream end with EOF standing in for a bare URL's terminator, and the reader's clean terminal (`[DONE]`, injected terminals) drains the hold as a synthetic content chunk routed through the full pipeline — format-shaped to the stream (`text_delta` on Anthropic wires, `content` on OpenAI), so the transformer, content callbacks, and observer see it. The buffered MCP replay path drains identically ahead of `[DONE]`. Benign responses are byte-identical (no tail duplication, no loss). Closes the defect the NENYA-164 audit found.
- **Stream-filter edge audit (NENYA-164)**: exhaustive every-offset fixtures (chunk sizes 1..N runes across strip/redact/block/log modes, multi-byte runes at every boundary) now pin the stream-filter contracts. The audit found a real defect — with small SSE deltas the ExfilGuard streams a violating URL's head ahead of its completion, leaking the URL and its query payload (the pre-existing straddle test passed vacuously); the hold-based fix is designed and prototyped but its reader integration (withheld-byte application on Pass, terminal-flush shaping per wire format, buffered-path Flush) is tracked as the NENYA-205 follow-up. The canary tool-args scan is pinned read-only (`TestScanArgsReadOnly`): a hit refuses the call, never rewrites arguments.
- **Slow-client eviction (NENYA-155)**: `server.stream_stall_timeout_seconds` (default 60s, `0` disables) bounds a single client write on the streaming routes — the deadline is re-armed before every write/flush via `http.ResponseController`, so only a write that cannot complete (a client that stopped reading while the provider keeps producing) trips it; a slow provider with idle gaps never does. On a breach the upstream dispatch is cancelled through the existing client-disconnect path and the event is classified `client_stalled`: no provider cooldown or breaker charge, only `nenya_client_stalled_total{model,provider}` telemetry. Stuck readers can no longer pin handler goroutines or upstream connections. Enabler: the metrics `responseWatcher` now exposes `Unwrap()` so `http.ResponseController` can reach the real writer through it.
- **Stall terminals carry the structured contract (NENYA-156)**: the mid-stream idle watchdog already existed (`stream_idle_timeout_seconds` + the thinking-aware extension); this closes the failure-semantics gaps. The stall terminal now carries `error_kind=provider_timeout` (Retryable + ShouldFailover) alongside the `gateway_error` event and `[DONE]` framing — verified: the stalled target takes a cooldown charge and the truncated stream is never cached (NENYA-27, existing tests pinned). The `/proxy/` passthrough path no longer aborts silently on a stall: it emits the same structured terminal (always separated by an SSE event boundary, so a truncated final frame cannot swallow it) and records stall telemetry (`nenya_stream_stalled_total{model="",provider=...}` — passthrough has no model concept).
- **Mid-stream failover on policy refusals (NENYA-191)**: a provider declining generated content is a policy outcome, not a provider fault. A refusal/safeguard terminal before any client-visible output (OpenAI `finish_reason: content_filter`/`refusal`, Anthropic `stop_reason: refusal`, Gemini `SAFETY`/`PROHIBITED_CONTENT`/`BLOCKLIST`/`SPII`/`IMAGE_SAFETY`/`RECITATION`) or a policy-worded rejection payload now fails the stream head over to the next target synchronously — WITHOUT charging cooldown/breaker — when one exists; on the last target the refusal stream is forwarded so the client sees it. Once renderable content was delivered, the refusal terminal is the outcome: the stream is terminal, never re-dispatched, and (NENYA-27) never cached. A relayed upstream 4xx body worded as a content-policy rejection surfaces as `error_kind=policy_refusal` (request-scoped, failover-eligible). The /v1/messages route shares the chat failover taxonomy. Metrics: `nenya_stream_bootstrap_total{outcome="refusal_failover"|"refusal_forwarded"}`.
- **Transient-failure taxonomy matches field reality (NENYA-168)**: Cloudflare's origin-failure statuses (520 unknown error, 521 origin down, 522 connect timeout, 523 unreachable origin, 524 origin timeout, 525/526 TLS handshake failures) joined the built-in retryable set — a provider behind Cloudflare returns them for a live, degraded edge, and they can succeed on a retry or another target (per-provider `retryable_status_codes` still replaces the set entirely). Anthropic's overage (pay-as-you-go billing) signals no longer schedule cooldowns: an overage reset is a billing-cycle boundary, not a retry horizon, so `Retry-After` is skipped on an overage-only rejection (the representative claim names overage, or the overage claim is the only rejected one) and overage-named reset fields in a body are ignored. A **model-not-found** error is now a *target* fault rather than a client-class error: it gets its own breaker class (404, or a 4xx naming a missing/unknown/deprecated model), cools the target down and locks the model on it, and the sweep fails over to a target that serves the model (the client sees the error only when no target remains). A capacity/overload rejection that is *not* shaped as an error envelope (e.g. `{"message":"model is at capacity"}`) now releases the NENYA-45 bootstrap buffer for failover, sharing one overload phrase list with the breaker's capacity class.
- **Per-key isolation for upstream-issued resource ids (NENYA-189, IDOR class)**: Nenya-side state keyed by upstream-issued ids can no longer be addressed across API keys. Gemini thought signatures (keyed by upstream tool-call ids) are cached under a per-API-key namespace — key B presenting key A's tool-call id gets a miss, not key A's cached reasoning state. The semantic response-cache similarity index is partitioned per auth identity and per model: a near-identical prompt from key B — or for a different model under the same key — can never be served key A's cached response (the fingerprint namespace this partition keys on was widened by NENYA-154; see the entry below). `/v1/responses`, `/v1/files`, and `/v1/batches` remain pure passthrough (upstream-enforced ownership; documented inventory decision in internal/proxy/responses.go). Cross-key isolation is covered by tests at the cache and proxy layers.
- **Fail-closed boot on weak credentials (NENYA-192)**: startup now refuses to serve traffic when the primary `client_token` or an `api_keys` entry token is empty, a publicly known placeholder (`changeme`, `test-client-token`, `your-api-key-here`, … — exact or as an unambiguous phrase), an unexpanded template or shell variable (`<your-token>`, `$VAR`, a pasted `$(openssl …)` command), a trivial word+digit value (`password123`), a repeated single character, or shorter than 16 characters; provider keys are checked for the placeholder/template/empty-as-keyless classes (no length floor — local and proxy upstreams legitimately use short shared secrets); config-file credentials (`providers.<name>.api_key`, `providers.<name>.accounts[].credential`) get the same placeholder/template/empty classes and gate both boot and SIGHUP reload — closing the class behind the 0.13.0 quick-start literal-token bug (peer precedent: LiteLLM #42019). The refusal names the credential, its source, and the remediation (`nenya secret set [--provider <name>]`; api_keys tokens are edited in the secrets document); the writers (`secret set`, `config set` on credential keys) apply the same checks so they cannot produce a boot-refused document; `NENYA_ALLOW_WEAK_SECRETS=1` is the documented dev-only escape hatch (a warning is printed once while it is set). Demo docs and the `mise run run` task updated for the placeholder demo secrets. **Upgrade note:** installs with placeholder credentials will refuse to boot — see the "Upgrading from earlier versions" section in docs/SECRETS_FORMAT.md
- **Slow calls as circuit-breaker failures (NENYA-153)**: Nenya's breakers opened only on errors, so a provider that answered but took minutes never tripped and traffic kept pooling on a degraded target. With `governance.slow_call_threshold_seconds` (per-agent override `agents.<name>.slow_call_threshold_seconds`, `0`/absent = off, negative or above 24h rejected at boot), a call slower than the threshold is charged to the breaker as a failure **while the client still receives the answer**: only the breaker sees the slowness. The streaming clock is the time-to-first-effective-output (NENYA-178), so a slow-thinking model is not punished for reasoning time, and the buffered paths use the whole call (dispatch to body read). A slow call is decided before the success is recorded, so it clears neither the consecutive-failure streak nor a half-open probe — it re-opens the circuit. The served buffered chat path now also records a **success**, so a half-open circuit can recover on buffered-only traffic (previously it recorded no outcome there and could burn its probe slots). Policy-blocked and terminal non-provider exits release the probe slot without recording an outcome. Scope: the chat paths and the buffered MCP replay path; the passthrough endpoints record no breaker outcome. Exposed as `nenya_slow_calls_total` (agent/model/provider labels) and counted in `nenya_cb_failures_total{key}`; the resulting circuit state is visible in `/statsz`.
- **Time-to-first-effective-output measurement (NENYA-178)**: Nenya recorded only the upstream response-header latency, so a target that answers slowly on the first token looked identical to a fast one — and a provider that answers-but-takes-minutes never trips the circuit breaker. Streaming requests now record the time to the first **effective output** frame per model+provider: the protocol-aware first token (the first OpenAI choice's content/tool-call delta, an Anthropic `content_block_delta` carrying text or tool input, or a `content_block_start` opening a tool block (`tool_use`/`server_tool_use`/`mcp_tool_use`), a Gemini candidate part bearing text/functionCall/inlineData/executableCode/codeExecutionResult/fileData) and never a keepalive, an empty delta, a bare/empty block opening, a block close, a role-only handshake, or a usage/metadata frame. Reasoning-only frames are excluded unless `governance.ttft_include_reasoning` is set, so slow-thinking models are not measured as slow-to-first-token. The clock starts at dispatch and stops at the first effective frame; the first attempt of a stream measures it (a continuation re-dispatch does not, since the client already received output), and a buffered (non-streaming) request never records one. Exposed in `/statsz` (`latency.<model>:<provider>.median_ttft_ms`, `ttft_sample_size`) and as the `nenya_ttft_seconds` histogram; the tracker's `TTFT(model, provider)` lookup feeds latency-aware routing, and the slow-call circuit breaker (NENYA-153) consumes the same per-request measurement. The same classifier now drives the NENYA-45 bootstrap head probe, so the two cannot drift apart; as a consequence the buffer no longer releases on a bare Anthropic block opening or a close, nor on an empty/signature-only Gemini part (it still releases on any OpenAI-shaped content, tool call, refusal, audio, or reasoning delta).

### Changed

- **Decision-only models are non-chat on every provider (NENYA-180)**: the `non_chat_models` classification had a built-in default only for the `zen` provider, so a provider that started advertising a decision-only model (OpenRouter, TypeSafe direct, another Jev reseller) exposed it as chat-routable and only failed at dispatch with an upstream error. The well-known typed-decision family (`^jev-`, TypeSafe Jev / System One) is now a **provider-agnostic built-in default** (`config.DefaultNonChatModels`): every provider whose own `non_chat_models` is omitted inherits it, so such a model never enters the merged catalog or `/v1/models` and a chat request naming it fails fast with `400 error_kind=invalid_request`. Presence is honoured (an explicit list — including `[]` — replaces the defaults, which is how a provider opts out), and the default is applied both in `ApplyDefaults` and in `gateway.New`, so a config built in code gets it too. The drops are no longer silent: `nenya_non_chat_models_dropped_total{provider}` counts the classification events (fetch-time filter, the pre-catalog path, and the catalog merge, which now reports what it dropped) and the dropped model IDs are logged at debug. The static-model backfill honours the classification too, so a backfilled model cannot re-enter the catalog and be counted twice, and System One owner selection is deterministic (sorted by provider name) so two Jev resellers cannot flip the target between restarts.
- **Tool JSON-schema sanitization hardening (NENYA-172)**: tool schemas are now normalized for cross-provider transport instead of being forwarded verbatim, closing the class of upstream schema-sanitization fixes (CLIProxyAPI 7fac6b1, e56abd5, 37ce368, f668ac4, c93978c, 4b4a444, e1e3a81, ffe6ad3, 2eb8dd1, b532db9, 320100e, 5af6cd7, e3e97ad, 369df97, 75b854e). **Fixed:** the tools/list decode was lossy (root-level `$ref`, `$defs`, `items`, `oneOf`/`anyOf`, and constraints were silently dropped, and an object-valued `additionalProperties` failed the whole tools/list parse, dropping a server's tools) — the schema now round-trips every keyword and the argument guard sees the whole declaration. A new `internal/jsonschema` package (stdlib-only leaf) sanitizes the schema before it is injected (MCP path and the Anthropic adapter both ways): dialect/meta keywords and the definition table are stripped, local `$ref` pointers are inlined with a cycle cap (unresolvable → the empty schema), bare boolean subschemas are widened while a boolean `additionalProperties` is preserved, the type is lowercased and inferred from `properties`/`items`, a pattern is dropped only when it uses a Unicode property escape or when RE2 cannot compile it and it uses no ECMA-only construct (lookaround/backreference/named group), so a valid ECMA-262 pattern is never lost, and the patternProperties fast-path bypass is closed — every subschema position the sanitizer knows is walked, and NUL/C0 control characters are stripped from strings. A parameterless tool now gets `{"type":"object","properties":{}}` instead of `{"type":""}`. MCP tool names are charset-sanitized, capped at 64 characters with a deterministic digest suffix, and deterministically disambiguated on collision. The sanitizer runs on the single request path (`SanitizePayload`), so it covers every provider rather than only the Anthropic adapter, and the MCP registry advertises exactly the name it dispatches on (a namespacing collision can no longer make two servers advertise one function name; registration order is deterministic). The lossless decode also made the argument guard's 16-level schema cap reachable for a declaration the typed decode used to truncate: such a call fails closed (the declaration cannot be validated in full) instead of being partially checked. Fuzzing: `FuzzSanitizeToolSchema` (found and closed a nested-`$ref` key, a DEL keyword name, control characters in a pattern/required/type name, and a non-idempotent `type` shape), `FuzzSanitizeToolName`, `FuzzInputSchemaDecode`, plus a committed adversarial schema corpus (`internal/jsonschema/testdata/schema_variants.json`). Out of scope (documented in MCP_INTEGRATION.md): a regex RE2 accepts but a provider's flavor rejects, a `$ref` into a definition table that is not in scope, and the draft-07 tuple `items` form.
- **Locally generated summaries cannot act as instructions (NENYA-148)**: every site where locally generated summary text re-enters the conversation is hardened against the compaction-self-injection class (opencode #36682: a summary executed its own "Next Move" section as user instructions). The window compaction summary, the context-limit retry summary and the bouncer's local rewrite are now produced and placed as inert data: summaries are wrapped in the untrusted-content delimiters with a summary provenance source (`summary:window`, `summary:context-limit`) after a `SummaryPreamble` marker (embedded envelope tags are defanged); action-plan sections (next steps/moves/actions, action items/plan/steps, to-do, follow-ups, remaining work — whole-line or inline) are stripped at insertion time, and the three summarizer prompts now require descriptive prose only; a summary is never injected as a `user` turn (the window summary is a `system` context marker, the context-limit summary an `assistant` one, and the window continuation cue was reworded to a descriptive marker); and the bouncer — which must keep the caller's own role because it rewrites the caller's request — removes any action-plan section its local engine introduced that the source text did not contain (list-marker and reflow normalization keeps a plan the engine merely reformatted), treating an all-plan rewrite as an engine failure. Only model-generated heads are enveloped (a deterministic truncate/tfidf head stays verbatim), the agent's leading system messages survive context-limit summarization, the shipped head reserves room for the envelope within `summary_max_runes`, and the tool-prune placeholder collapses whitespace and drops quotes in its client-controlled label. Documented in `docs/INJECTION_DEFENSE.md` (Layer 7) with its honest limitations.
- **Adversarial variant-taxonomy audit of the tier-1 gates (NENYA-147)**: the deterministic URL/injection/tool-argument gates are now audited against the upstream bypass taxonomy with committed adversarial corpora and fuzz targets. **Fixed (real bypasses):** the ExfilGuard URL policy only recognized dotted IPv4 literals and single trailing dots, so a private destination spelled as an integer (`http://2130706433/`, `0x7f000001`, `0177.0.0.1`, `127.1`) or with an IPv6 zone identifier (`http://[fe80::1%25eth0]/`) read as an ordinary hostname and passed when no allowlist was configured; the destination helpers now live in `internal/netutil` (a new `ipdeny.go`; the package already hosted the transport policy) and are shared with the MCP argument policy (so the deny set also covers CGNAT, multicast/broadcast and NAT64 embeddings) and the host is normalized (lowercase, every trailing dot, zone cut) before matching. The MCP argument policy checked only the first whitespace-separated token of a string and only `http(s)://` prefixes, so a URL embedded in a command line (`curl http://169.254.169.254/`), a scheme-relative `//host`, a non-http scheme with a denied host, and a destination-shaped bare token (`10.0.0.5`, `10.0.0.5:22`, `localhost:8080`, `db.internal`) all passed — all are now denied (a standalone numeric `8080`/`2025`/`0644` is not treated as an address, and a bare single-label `localhost` counts only as the whole value or with a port/path so prose is not rejected). The ExfilGuard also now denies special-use hostnames (`localhost`, `.local`, `.internal`) as `private_host` instead of passing them as ordinary hostnames. The tier-1 injection pass matched only ASCII whitespace and the original characters, so a keyword split by a non-breaking space, U+2028, a fullwidth homoglyph, an ANSI escape, a soft hyphen, a ZWNJ, a variation selector, or a Unicode tag character evaded every pattern; a normalized copy is now matched — ANSI escapes, C0 controls (incl. a lone ESC/DEL), extended invisible/tag characters, and the hidden-text set are each removed **and** space-substituted (two candidates, plus the pre-strip form when the hidden-text strip ran), fullwidth forms are folded, and Unicode space separators collapse to a plain space — adopted only when it reveals a new pattern or re-neutralizes a span of an already-counted one, so benign content is never rewritten by normalization alone. The `disregard` pattern required a second whitespace run after "all "/"any ", so the natural "disregard all instructions" never matched. **Corpus and fuzzing:** `internal/{stream,pipeline,mcp}/testdata/*_variants.json` with `TestExfilGuardVariantTaxonomy`, `TestInjectionVariantTaxonomy`, `TestToolArgURLVariantTaxonomy`, plus `FuzzExfilURLVariantScan`, `FuzzNormalizeForMatching` and `FuzzDenyURLHost`; documented limitations (homoglyph blocks outside fullwidth, UTF-16, literal escape text) are committed as non-detecting cases, and the remaining out-of-scope shapes (the RFC 2765 IPv4-translated form, 6to4/Teredo, punycode/DNS-based destinations) are listed in `docs/INJECTION_DEFENSE.md`.
- **Budget/rate-limit state follows the failover path (NENYA-188)**: the per-key daily token budget is reserved once per logical request and the per-provider daily budget is now re-checked on **every dispatch**, not only the first target. **Fixed:** a provider-budget-exhausted target used to fail the whole request with a typed 429 even when a later target had headroom; it is now skipped (logged per skip) and the sweep continues, reporting `429` with reason `provider_budget` only when no target reached a provider (a later target that was dispatched — including one rejected for an HTML body — still reports its own outcome). The check runs last among the pre-dispatch guards, so a target skipped for another reason does not consume provider budget, and it now covers the paths that previously bypassed it entirely: the MCP multi-turn loop (each iteration is one dispatch) and the stream-continuation re-dispatch. The MCP loop also reserves the caller's per-key budget before its first dispatch (it does not go through the chat retry loop), so a budgeted key can no longer drive an unbudgeted MCP tool loop. A budget denial answers in the client's wire format (SSE for streaming requests and the MCP tool loop, JSON otherwise) with the same `error_kind=rate_limited`, and the budget-denial metric is attributed to the key name (`nenya_auth_denials_total{key_name=…,reason=…}`) instead of the agent name. Operator-visible: a `fill`-tier key on a failover chain whose early targets are budget-exhausted is served by a later target instead of failing the request (a `sticky_provider` agent keeps its sticky semantics, where a dispatch-failure skip blocks the pair).
- **Usage accounting single-claim semantics (NENYA-193)**: one usage record per dispatch, attributed per attempt. A **dispatch** (initial attempt, failover, same-target retry, context-limit/parameter-reject retry, stream continuation) is one billable upstream call; within a dispatch the record is claimed exactly once. **Fixed:** a streaming response whose provider reports usage in several cumulative chunks called `BillingTracker.RecordSpend` once per chunk, so one dispatch counted one request per usage chunk — the first chunk that reports usage now claims the request and later deltas only add spend (`BillingTracker.AddSpend`), keeping the cost exact. A dispatch is claimed whenever it reported usage, even when the model has no pricing entry (cost 0). **MCP loop:** every buffered iteration is one dispatch and now claims its usage (Stats, cache/reasoning metrics, cost and one billing request) via `recordMCPIterationUsage`; previously the whole MCP path recorded no cost or spend at all, and once a per-iteration claim exists the terminal paths would double count a buffer they observe again — a per-buffer claim flag (`usageClaimed`) makes the terminal paths idempotent, and the replay paths' buffers (whose usage was previously lost) are now recorded by their own iteration claim. **Operator-visible change:** `total_requests` (in `/statsz` billing stats) now counts dispatches instead of usage chunks on the streaming path, and MCP requests now contribute cost and spend. The dead `recordChatUsage` helper was removed; `BillingTracker` gained `AddSpend` (cost without a request claim) and its read/reset methods are now nil-safe as documented. Semantics and the per-dispatch attribution rule are documented in `docs/BILLING.md` ("Single-claim semantics").
- **Usage normalization invariants across format conversion (NENYA-167)**: every upstream usage object is now reduced by one shared normalizer (`stream.NormalizeUsageTotals`) used by both the streaming reader and the buffered recorder, so each dimension is counted exactly once whichever wire shape carried it. **Fixed:** Anthropic-native streams recorded no usage at all (the reader only looked at the OpenAI-shaped top-level `usage` with `prompt_tokens`/`completion_tokens`; Anthropic nests the input usage under `message_start.message.usage` and reports `input_tokens`/`output_tokens`), so Anthropic-format providers now record prompt/output/cache tokens; Gemini-native `usageMetadata` (a nonstandard placement) is read, with `thoughtsTokenCount` folded into the completion total because `candidatesTokenCount` excludes it; a usage-only final chunk with no `choices` (Together-class) is read; the Anthropic→OpenAI buffered conversion no longer drops `cache_read_input_tokens`/`cache_creation_input_tokens` (it folds them into the prompt total and re-publishes them as subsets) and the reverse conversion splits `input_tokens` back out instead of reporting a total that double-counts with the cache counters; buffered usage is recorded from the upstream's own wire shape **before** format conversion and egress policies, so a converted (or blocked) reply no longer loses the tokens the upstream billed (the Anthropic-client→OpenAI-upstream path recorded nothing before); and the OpenAI→Anthropic streaming transformer publishes the real upstream usage on the final `message_delta` when the provider reports it before the finish chunk (previously always a character-count estimate). **Known limitation:** with the standard `stream_options.include_usage` ordering the usage-only chunk arrives *after* the finish chunk, by which point the closing `message_delta` is already emitted, so the estimate stands for those providers; `message_start` also still carries `input_tokens: 0` (the upstream reports usage at the end of the stream). Nenya's own accounting is unaffected in both cases — the reader records the real usage before the transformer runs. Streaming usage is still reported in a trailing chunk, so a mid-stream termination (egress block or stream cut) loses that trailing chunk — only the buffered path is fully committed ahead of downstream failures. Where a usage object carries an OpenAI-style input total together with the Anthropic-native cache field names and no cache decomposition, the cache semantics are inferred (Anthropic reading) and a warning names the provider and model. Invariants and the per-shape mapping are documented in `docs/COST_MODEL.md`. **Operator-visible `/statsz` change:** for Anthropic-native and Gemini-native usage, `cache_hit_ratio` moves from `hit/(hit+creation)` (or `0` for Gemini) to the true `hit/prompt`, and `cache_miss_tokens` goes from `0` to the uncached remainder, because the cache counters are now derived so that they sum to the input total.
- **Response-cache fingerprints and semantic-cache sharing (NENYA-189)**: auth-scoped cache fingerprints are now `"auth:" + hex(sha256(bearer token)) + ":" + hex(sha256(payload))` (previously a single combined SHA-256); the semantic cache partitions its similarity index per bearer token and per model. **Operator-visible hit-rate change:** multi-key deployments no longer share semantic cache entries across keys — each key builds its own semantic namespace (single-key deployments are unaffected). In-memory state only; restarts are unaffected
- **Dependency policy made absolute; multi-replica coordination out of scope (NENYA-134 decision)**: Nenya will not use any external code or dependency. The Redis-based multi-replica state externalization design was withdrawn unimplemented — coordinated state (rate limits, budgets, breakers, caches) is per-replica by design, and single-replica is the supported topology for enforcement. Operators scaling to multiple replicas accept multiplied provider-side limits and fragmented cooldowns/budgets (documented in DEPLOY_KUBERNETES.md)
- **Metric family renamed `nenya_billing_spend_usd` → `nenya_billing_spend_cents_total` (NENYA-198 follow-up)**: the series always carried cents (the HELP text claiming USD was wrong, and `docs/BILLING.md` documented cents), so the name now matches the unit. Update dashboards/alerts keyed on the old name; the HELP also documents that the series is cumulative since process start and is not rewound by `ResetSpend`
- **`BillingTracker.TotalSpendUSD` renamed to `TotalSpendCents` (NENYA-198 follow-up)**: the exported counter stores cents (it always did — the name lied); Go/external consumers of the field must rename accordingly
- **Cost-recording boundaries hardened (NENYA-198)**: `Metrics.RecordCostWindow`, `CostTracker.RecordUsage`, and `BillingTracker.RecordSpend` convert USD via the new `util.SafeMicroUSD`/`util.SafeUSDCents` — NaN, Inf, and magnitudes that would saturate the int64 conversion are now skipped instead of recording `MaxInt64` costs (arm64 saturation made a single hostile usage payload permanently poison per-model cost totals and routing cost normalization); `Routing.calculateScore` keeps the neutral 0.5 for latency/cost dimensions whose observed range is degenerate (a single measured target no longer normalizes against a sentinel range), and the stale-latency eviction sweep is throttled off the per-record hot path
- **Response-cache fingerprints now carry the effective content-policy identity (NENYA-154)**: the fingerprint namespace is `hex(sha256(sha256(auth token) ‖ sha256(policy scope)))`, where the policy scope is the resolved agent (including its system-prompt identity, `cache_aware`, and `cache_salt`), the client wire format (`openai`/`anthropic` — the cache stores post-transform bytes, so a format crossing would corrupt the stream), and the security-relevant guardrail configuration: output redaction and window, the redaction pattern set/preset/label, entropy thresholds, `bouncer.fail_open`, the blocked-execution (response stream-filter) patterns, the prefix-cache `skip_redaction_on_system` relaxation, the injection detector global section plus per-agent override, spotlighting, the egress guard hosts/query-cap/action, the canary, and the advisory judgment sites (`judgments`, `tfidf_rerank`) including their engine-chain identity. A body cached before a guardrail existed — or under a more permissive agent/global policy — can no longer be replayed on a cache HIT or reached as a near-duplicate; because the scope lands in the same segment the semantic index partitions on, tightening a policy also starts a fresh semantic namespace (peer precedent: GoModel #971, where an unredacted credential was served from a pre-redaction cache entry). The scope covers the guardrail inputs; non-security request-shaping knobs (context trim limits, window/compaction, token calibration, routing) remain outside the pre-pipeline cache key, as documented. **Operator-visible hit-rate change:** editing any of those knobs (or giving an agent its own overrides) yields misses for entries stored under the previous policy; in-memory state only, restarts unaffected — and a SIGHUP reload already builds a fresh cache, so this is defense-in-depth (in-process changes, cross-agent and cross-format isolation) rather than the live reload exposure
- **Per-key MCP tool caps + MCP credential hygiene (NENYA-183)**: a key can no longer invoke MCP tools beyond its grant. `api_keys[].allowed_tools` (empty = every tool the agent's MCP configuration exposes) is intersected with the agent's servers when tools are injected into the upstream request and enforced again at dispatch, including the auto-search/auto-save dispatches — a model naming an ungranted tool gets a refusal result instead of a call. `mcp_servers.<name>.required_headers` declares the headers a server needs: a server missing one is never connected, and a request whose agent selects it fails closed with `503 error_kind=mcp_unavailable` rather than silently running without its tools; a server that refuses the configured credential (401/403) is recorded as unavailable for the same reason. A credential the server refuses at runtime (401/403 on a dispatched call) takes the server out of service for a 60-second cooldown — requests that need it fail closed during the window, a successful call re-enables it immediately, and `/statsz` lists unusable servers with the reason. MCP server URLs are now validated (absolute `http`/`https`, host required, no embedded credentials, plaintext refused for non-local hosts) and redirects are refused when they leave the configured origin or downgrade to plaintext — previously any URL was accepted and redirects were followed without re-validation, so a server could redirect the configured credential to another host. Credential hygiene: `nenya describe --json` redacts `providers.<name>.api_key`, `providers.<name>.accounts[].credential`, proxy userinfo, and every `mcp_servers.<name>.headers` value (names stay visible), and `nenya config set` preserves a config file's permissions (default `0644` for a new file) so an operator can keep a credential-bearing file private without breaking the dynamic-user systemd unit. At-rest encryption of MCP headers is deliberately not implemented and documented in `docs/SECRETS_FORMAT.md` (config is operator-managed; treat it as a secret file).
- **Session state is bound to the authenticated API key (NENYA-196)**: session-derived state — sticky pins, account/credential affinity, the NENYA-39 affinity fork, and the synthesized `X-Opencode-Session` header — is now keyed by the caller's subject (the digest of the API key's token) in addition to the conversation opener (agent + system prompt + first user message). One API key can no longer read another key's pinned provider/model/account by presenting the same opener, so a pin (and the credential preference it carries) is only ever acted on for the key that created it. **Operator-visible change:** pins no longer share across keys (a deployment with N keys keeps up to N× the distinct sessions, bounded by the same LRU cap and TTL, so idle pins evict sooner), and the synthesized upstream session id differs per key for the same conversation. A client-supplied `X-Opencode-Session` header is still forwarded verbatim, so upstream session aliasing across keys remains possible when a client knows the id — that is the provider's session namespace, not Nenya's. **Upgrade note:** rotating an API key's token drops that key's pins and affinity forks (the subject is the token digest) and changes its synthesized `X-Opencode-Session`, so the next upstream request opens a fresh provider-side session for it.
- **Fail-closed authorization hardening (NENYA-196)**: an API key with an unparseable `expires_at` is refused instead of being treated as never expiring; a key carrying an unrecognized role (or no role) is denied by both `AuthorizeAgent` and `AuthorizeEndpoint` instead of falling through to the permissive branches; a chat request that omits `model` is rejected with `400 invalid_request` before routing instead of skipping per-key agent scoping; and the `/v1/responses` create endpoint requires a model that can be read as a non-empty string (an unparseable body, a non-object body, or a wrong-typed model is rejected rather than forwarded unscoped; id-addressed sub-paths such as retrieve/cancel/delete/compact still pass through without a model). Denial reasons `invalid_expiry`, `missing_model`, and `invalid_key` (an unscoped `/v1/responses` request) are new metric labels. These are defense-in-depth layers behind the load-time validation, not new configuration requirements.
- **Config reference validation gates boot, `-validate`, and reload (NENYA-196)**: `api_keys[].allowed_agents` must name configured agents (admin keys are exempt because the field is inert for them; the check is skipped when discovery runs with `auto_agents`, since those agents are generated after validation) and a non-admin key that can reach the chat routes with an empty list logs a warning that it grants every agent; `agents[].mcp.servers[]` must name configured `mcp_servers`; and `sticky_session_ttl_seconds` is validated for every agent strategy (pins and credential affinity resolve for all of them). A dangling reference now refuses startup, `-validate`, and the SIGHUP reload (it previously degraded silently at request time), and an out-of-range `sticky_session_ttl_seconds` is refused by the same three gates (it was previously honored at runtime, with no clamp). Two enabled API keys may no longer share a token, a `name`, or a token equal to the primary `client_token` — each collision made the authenticated identity (and therefore per-key limits and attribution) ambiguous — and an enabled key must set a non-empty `name`.

Skipped while a tool call is in flight. Metrics: `nenya_stream_continuations_total{reason}`, `nenya_stream_interrupts_total{reason}`
- **Provider model allowlists** (`providers.<name>.allowed_models`): RE2 regex patterns restricting which models are usable per provider. Non-matching models are dropped from `/v1/models` discovery and blocked in routing (400 `model_not_found`); matching static-registry models are re-added when discovery omits them. Empty/omitted = all models allowed.
- **Early stream-error failover** (`governance.early_stream_error_failover`, default true): upstream SSE error events at the stream head (before HTTP headers are committed) trigger failover to the next target in the agent chain instead of forwarding error bytes. Metric: `nenya_stream_early_errors_total{outcome="failover|forwarded_last_target"}`

### Changed

- Removed the blanket client-side timeout that could interrupt long-running streams mid-flight; stall detection (`stream_idle_timeout_seconds`) now solely governs stalled upstreams

### Fixed

- `bouncer.enabled=false` is now honored; the interceptor chain is rebuilt on SIGHUP reload
- Stream endings without a terminal event are classified correctly, and the circuit breaker is no longer penalized for gateway-side errors
- Session pin last-seen timestamps are updated under lock (data race)
- `trackInFlight` cleanup is invoked via `defer` so the in-flight request counter cannot leak on early returns
